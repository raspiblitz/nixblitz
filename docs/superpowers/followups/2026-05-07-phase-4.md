## Cosmetic gaps in dashboard tiles

### `mempool_txs` (bitcoin tile Mempool row) — upstream-blocked

**Where it's bound:** `common/lib/src/services/dashboard/bundled/manifests/bitcoin.json`
**Why missing:** two upstream gaps in blitz-api:

1. `BTC_MEMPOOL_STATUS` SSE event is declared in
   `app/api/utils.py`'s catalogue but **nothing broadcasts it**.
2. There's **no `/bitcoin/get-mempool-info` REST endpoint** either —
   `app/bitcoind/router.py` exposes `/btc-info`, `/get-block-count`,
   `/get-blockchain-info`, `/estimate-fee`, `/get-network-info`,
   `/get-raw-transaction`, `/block-sub`, but no mempool wrapper.

**Fix:** upstream PR to `fusion44/blitz_api` adding either:

- a periodic `BTC_MEMPOOL_STATUS` broadcaster (mirror the
  `_handle_gather_bitcoin_status` pattern in `app/bitcoind/service.py`),
  OR
- a `GET /bitcoin/get-mempool-info` REST endpoint wrapping bitcoind's
  `getmempoolinfo` RPC.

The streamer's `EVENT_TO_TILE` already maps `btc_mempool_status`
optimistically; once the broadcaster lands the tile row populates
without further plugin changes.

(`chain_name` / `chain_color` was the other gap in this section —
resolved by the streamer's one-shot `/bitcoin/get-blockchain-info`
poll at startup.)

## Architectural — unify plugin manifest shapes

The 3 official plugins (`electrs`, `lnbits`, `tailscale`) still use
the Phase-1 `manifest.config` map for declaring user-editable
fields. The blitz-api plugin uses Phase-3 `manifest.configSchema.fields`
(an embedded `AppManifest`).

Both work — `plugin_config_view` handles both shapes since the
post-9c fix. But the unified design intent (path A) was one shape
to learn. Migrating the 3 plugins:

- Move `config.<field>` map → `config_schema.fields[]` array.
- Same field semantics; just a structural rename.
- Each plugin gets its own commit in the official-plugins repo.
- After all 3 migrate, drop the legacy `manifest.config` parsing
  from `PluginManifest.fromJson` (one round of `dart analyze` will
  confirm no remaining consumers).

Low priority — operators don't see this, plugin authors will only
see it when adding a new plugin.
