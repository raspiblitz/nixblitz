## Cosmetic gaps in dashboard tiles

### `mempool_txs` (bitcoin tile Mempool row) — upstream-blocked

**Where it's bound:** `common/lib/src/services/dashboard/bundled/manifests/bitcoin.json`
**Why missing:** two upstream gaps in blitz-api:

1. `BTC_MEMPOOL_STATUS` SSE event is declared in
   `app/api/utils.py`'s catalogue but **nothing broadcasts it**.
2. There's **no `/bitcoin/get-mempool-info` REST endpoint** either —
   `app/bitcoind/router.py` exposes `/btc-info`, `/get-block-count`,
   `/get-blockchain-info`, `/estimate-fee`, `/get-network-info`,
   `/get-raw-transaction`, `/block-sub`, but no mempool wrapper.

**Fix:** upstream PR to `fusion44/blitz_api` adding either:

- a periodic `BTC_MEMPOOL_STATUS` broadcaster (mirror the
  `_handle_gather_bitcoin_status` pattern in `app/bitcoind/service.py`),
  OR
- a `GET /bitcoin/get-mempool-info` REST endpoint wrapping bitcoind's
  `getmempoolinfo` RPC.

The streamer's `EVENT_TO_TILE` already maps `btc_mempool_status`
optimistically; once the broadcaster lands the tile row populates
without further plugin changes.

(`chain_name` / `chain_color` was the other gap in this section —
resolved by the streamer's one-shot `/bitcoin/get-blockchain-info`
poll at startup.)

## Pre-existing — pulled forward for context

These were opened earlier in the project and aren't Phase-4-specific
but are tracked alongside this work:

- **Issue #26 (testing strategy):** the three-tier proposal — eval
  matrix on every PR, NixosTest VMs for activation paths, operator
  simulation for the TUI. Pick up post-Phase 5.
- **Issue #27 (plugin update security):** ✅ **resolved** —
  pin-to-rev + signer verification was already partially in place
  via `PluginMarker.signatureFingerprint` + `PluginSignatureMismatch`;
  the followup landed the TUI refresh UX:
  - `[r]` on the Plugins tab refreshes the highlighted plugin via
    `PluginRefreshView`. Signature mismatch shows pinned + new
    fingerprints + remove-and-re-add recovery hint. Hard-fails on
    key rotation (no silent acceptance).
  - `[R]` runs `refreshAll` via `PluginRefreshAllView` with the
    advanced/unchanged/failures/skipped partition rendered inline.
  - SIG column on the plugins tab shows the short fingerprint
    or `(unsign)` so operators can see at a glance which plugins
    will be rotation-protected.
  - "↑" prefix on STATUS marks rows whose pinned rev is behind
    upstream HEAD, joined against the daily update check's
    `pluginsAhead`.
