# v0.1 platform validation

Manual checklist for validating the x86 and Pi 5 install + runtime
flows after the recent session of changes (Pi 5 platform, plugin
signing TOFU, in-log search, FS watcher, update-flow re-auth, nvd
nixblitz visibility, pending-tile state, tile-layout rebalance,
electrs plugin).

Tick items as you go. If something fails, capture
`~/nixblitz.log` from the affected machine before retrying.

---

## Part A — x86 in a VM

### A.1 Pre-flight

- [x] Hypervisor available (Proxmox / qemu / virt-manager).
- [x] **NixOS 25.11 minimal ISO** downloaded.
- [x] VM provisioned: 4 GB RAM, 30 GB disk, UEFI, ISO first.

### A.2 Live boot + bootstrap

- [ ] VM boots from ISO; lands at `nixos@` shell.
- [ ] (Optional) `passwd` + `ip -4 addr | grep inet` to enable SSH from host.
- [ ] Bootstrap runs without error:
  ```
  nix run git+https://forge.f44.fyi/f44/nixblitz_ng \
    --experimental-features "nix-command flakes" \
    --no-write-lock-file --refresh
  ```
- [ ] TUI launches in **install mode** (auto-detected tmpfs root).

### A.3 Install wizard

- [ ] Auto-detected platform shows as `x86` (or `vm`).
- [ ] Disk picker lists the VM's disk (`vda` / `sda`).
- [ ] Pick disk → network = **regtest** → Lightning = **LND**.
- [ ] Confirm → log line shows
      `disko-install --flake $base#nixblitz-installer --disk main /dev/...`
- [ ] disko-install completes (partition / format / copy / bootloader).
- [ ] Reboot prompt appears.

### A.4 First boot

- [ ] GRUB picks the new generation; NixOS boots; TUI launches in **setup mode**.
- [ ] Sudo modal appears; default password `nixblitz` accepted.
- [ ] New admin password set without error.
- [ ] `nixos-rebuild switch` log shows `--flake $base#nixblitz` (the x86 attribute).
- [ ] If exit code 4 fires (logrotate-checkconf or similar
      activation-time warning), the wizard shows a yellow
      "completed with warnings" banner and `[Enter]` continues
      past it without breaking the flow.
- [ ] LND seed reveal screen presents `[A] show on screen` /
      `[B] continue without showing` choice with the recovery
      command (`sudo cat /mnt/data/lnd/lnd-seed-mnemonic`)
      visible on the choice screen.
- [ ] Pick A → 6×4 numbered grid renders 24 words; aezeed
      caveat (NOT BIP-39, doesn't restore into hardware
      wallets) visible. `[Y]` advances.
- [ ] All four core tiles (System / Hardware / Bitcoin / Lightning) render.
- [ ] Header strip shows `<lnd alias> | x86` (or `vm`) between
      logo and version.

### A.5 Daily-use smoke test

- [ ] Configure → toggle a value → Esc → orange `1 pending change` banner.
- [ ] Apply view shows the diff; `[a]` confirms; rebuild completes.
- [ ] Tiles do NOT blink to "waiting for event…" after the
      apply finishes (snapshot cache + REST prime keeps them
      populated across the data-source recreate).
- [ ] Footer hint includes `[a]` only when there are pending
      changes (omitted on a clean tree).

### A.6 Resume + drift behaviour

- [ ] During the wizard, exit at the seed reveal step (`Ctrl+C`
      or close SSH). Re-launch `nixblitz` — wizard resumes at
      the seed step rather than dropping to the dashboard or
      restarting from the password screen.
- [ ] On the dashboard: footer's `[r]: Refresh templates` is
      absent on a clean install (binary's embedded templates
      match disk).
- [ ] Hand-edit any file under `~/nixblitz/templates/`,
      relaunch the TUI — yellow "N template files differ"
      banner appears; `[r]` rewrites the file from the binary's
      embedded copy and routes to the apply view.

### A.7 Debug menu

- [ ] `Shift-D` opens debug menu. On regtest, "Generate regtest
      blocks" and "Regtest auto-miner (background)" both
      visible; non-regtest networks hide both.
- [ ] Generate regtest blocks: numeric input accepts digits
      (e.g. type `5` `0` for 50 blocks), Backspace trims one
      digit, `[g]` runs.
- [ ] Auto-miner: pick min=5s max=10s, `[s]` sudo-prompts then
      view flips to the running pane within ~2-4s. Journal tail
      shows `sleep Ns, then mine 1` lines.
      `bitcoin-cli -regtest getblockcount` in another shell
      advances. `[S]` stops.

## Part B — Raspberry Pi 5

### B.1 Pre-flight

- [ ] Pi 5 (8 GB strongly recommended).
- [ ] USB stick (≥4 GB) for the live image.
- [ ] Target storage: NVMe via M.2 HAT (preferred) or microSD.
- [ ] Build machine has Nix.
- [ ] Cachix configured on the build machine:
  ```
  nix --experimental-features "nix-command flakes" run nixpkgs#cachix \
    -- use nixos-raspberrypi
  ```
  (re-run with `sudo` for multi-user installs).

### B.2 Build the live image

- [ ] Build:
  ```
  nix --experimental-features "nix-command flakes" build \
    github:nvmd/nixos-raspberrypi/v1.20260707.1#installerImages.rpi5
  ```
- [ ] Heavy bits substitute from Cachix (no local kernel compile).
- [ ] `result/sd-image/*.img.zst` exists.
- [ ] Flash to USB stick (Raspberry Pi Imager, or
      `zstd -dc result/sd-image/*.img.zst | sudo dd of=/dev/sdX bs=4M conv=fsync`).

### B.3 Boot the Pi 5

- [ ] Insert USB stick; NVMe seated if installing onto NVMe; power on.
- [ ] Pi 5 boots from USB; **lands at `root@` shell** (upstream
      sdimage-installer default — quirk #1 in
      `getting-started.md` § 2).
- [ ] If the random root-password printout was garbled by other
      boot output (quirk #2), `passwd` on the local console
      sets a known one.
- [ ] `ip -4 addr | grep inet` shows the LAN IP.
- [ ] SSH from workstation works (`ssh root@<pi-ip>`).

### B.4 Bootstrap NixBlitz

- [ ] `nix-shell -p git` first (live image doesn't ship git —
      quirk #4).
- [ ] Bootstrap command includes the Pi 5 cachix flags so the
      first-run substitutes 16K-page-aligned binaries (quirk
      #5; without these the bootstrap SIGBUSes mid-fetch):
  ```
  nix run \
    --extra-substituters "https://nixos-raspberrypi.cachix.org" \
    --extra-trusted-public-keys "nixos-raspberrypi.cachix.org-1:4iMO9LXa8BqhU+Rpg6LQKiGa2lsNh/j2oiYLNOQ5sPI=" \
    --experimental-features "nix-command flakes" \
    --no-write-lock-file --refresh \
    git+https://forge.f44.fyi/f44/nixblitz_ng
  ```
- [ ] Build completes (5-30 min on the first run; Dart workspace
      builds locally, kernel + Pi 5 firmware substitute from
      cachix).
- [ ] TUI launches in **install mode** (detected via
      `VARIANT_ID=installer` in `/etc/os-release` — root is
      ext4 here, NOT tmpfs, so the older tmpfs-only check
      wouldn't have triggered).

### B.5 Install wizard (Pi 5 specifics)

- [ ] Auto-detected platform shows as `pi5`.
- [ ] Disk picker hides the USB stick we booted from (it's the
      `/` device on the writable-rootfs sdimage installer; the
      filter walks `/proc/mounts` for the device backing `/`
      when no `/iso` mount is present). Press `[s]` to override
      the filter and see hidden disks if you need to.
- [ ] Disk picker lists at least the NVMe (and any SD inserted).
- [ ] Pick **NVMe** (typically `/dev/nvme0n1`).
- [ ] Network = regtest; Lightning = LND.
- [ ] Confirm → log shows
      `disko-install --flake $base#nixblitz-pi5-installer --disk main /dev/nvme0n1`.
- [ ] Partitioning succeeds: GPT, FAT firmware (1 GB) + ext4 root.
- [ ] Closure copies (substitutes from caches).
- [ ] Bootloader installs into `/boot/firmware`.
- [ ] Reboot prompt appears.

### B.6 First boot from NVMe

- [ ] Power off → **pull the USB stick** → power on.
- [ ] Pi 5 boots from NVMe (no USB present).
- [ ] TUI launches in **setup mode**.
- [ ] Sudo modal accepts default `nixblitz` password.
- [ ] New admin password set.
- [ ] `nixos-rebuild switch` log shows `--flake $base#nixblitz-pi5`
      (the Pi 5 attribute).
- [ ] Header strip shows `<lnd alias> | Pi 5` between logo and
      version.
- [ ] LND seed reveal flow completes (see A.4 for the same
      checklist items — choice screen, A/B options, aezeed
      caveat).
- [ ] Dashboard renders all four core tiles.

### B.7 Pi 5 daily-use smoke test

- [ ] Configure → toggle → Esc → pending banner shows.
- [ ] Apply view diff renders; `[a]` confirms; rebuild completes.
- [ ] Bare `sudo nixos-rebuild switch --flake .` (no `#`
      attribute) builds the Pi 5 config — the hostname-keyed
      alias in `templates/flake.nix` resolves
      `nixosConfigurations.${hostname}` to `nixblitz-pi5` for
      Pi 5 systems.
- [ ] `nixblitz-regtest-automine.service` from the debug menu
      mines blocks successfully (`bitcoin-cli -regtest
getblockcount` advances). This catches the 16K-page
      jemalloc-sys class of issues — uv runs because blitz-api
      now follows our nixpkgs (see CLAUDE.md "Flake input
      rules").

## Part C — Cross-cutting features (run once on whichever platform you have on hand)

### C.1 Plugin install with TOFU signing

- [ ] `nixblitz plugin add forgejo:forge.f44.fyi/f44/nixblitz_official_plugins/tailscale`.
- [ ] Consent prompt shows a `signature:` line. Either:
  - `signed by SHA256:... [unverified key]` (commits are SSH-signed,
    operator has no allowed_signers), or
  - `(unsigned)` (commits actually have no signature).
- [ ] `[y]` proceeds.
- [ ] `~/nixblitz/config.json` shows `signature_fingerprint: "SHA256:..."`
      on the new entry (or omitted entirely if unsigned).

### C.2 Pending tile state

- [ ] Right after plugin add (before Apply), dashboard shows the
      new plugin tile in **yellow** with status `pending` and
      footer `awaiting Apply — \`<command>\` not on PATH yet`.
- [ ] After Apply, the tile transitions to its real state
      (green / yellow / red depending on the plugin).

### C.3 In-log search (Apply diff)

- [ ] In Apply view diff (any non-trivial diff): press `/`.
- [ ] Compose buffer appears at the bottom: `/_`.
- [ ] Type a term → `Enter` → first match scrolls into view.
- [ ] **Active match** is in NixBlitz orange (bold); other matches yellow.
- [ ] At least 3 lines of context visible above/below the active match.
- [ ] `n` advances to next match (cycles); `N` advances backward (cycles).
- [ ] Status bar shows `[i/N] /<query>`.
- [ ] `Esc` clears the search; matches stop highlighting.

### C.4 Update flow + re-auth-before-apply

- [ ] Dashboard → `[u]` Update → "Update entire system".
- [ ] Sudo modal appears (initial ensureFresh).
- [ ] Lock update + plugin refresh stream lines.
- [ ] Preview screen renders nvd diff.
- [ ] If the new build moved nixblitz, the diff lists it as
      `nixblitz: 0.1.0+oldrev → 0.1.0+newrev` (the version-suffix
      change makes nvd visible across commits).
- [ ] **Wait > 5 minutes on the preview screen** so the cached
      sudo timestamp expires.
- [ ] Press `[a]` Apply.
- [ ] Sudo modal re-pops (re-auth fix); enter password.
- [ ] Rebuild runs; outcome banner shows green "Update Complete"
      (NOT red "Update Failed").

### C.5 External-CLI reactivity (FS watcher, #18)

- [ ] TUI on Dashboard.
- [ ] In a second shell on the same host:
      `nixblitz plugin remove <some-installed-plugin>`.
- [ ] Within ~1 s the dashboard updates:
  - Pending-changes banner appears or increments.
  - The removed plugin's tile disappears.
- [ ] Inverse: `nixblitz plugin add <new-plugin>` from the
      second shell → tile appears (in `pending` yellow until Apply).

### C.6 Plugin action (privileged unit)

- [ ] Configure → plugins → any plugin with an Action declared
      (lnbits "Reset DB", electrs "Restart") → trigger.
- [ ] Confirmation prompt shows.
- [ ] Sudo modal pops if timestamp expired.
- [ ] `systemctl start --wait <unit>.service` streams output.
- [ ] Action completes; service is back up.

### C.7 Tile layout (cosmetic)

- [ ] Resize terminal to ~140 cols (3-column layout).
- [ ] Dashboard shows tiles in 3 columns; the partial last row
      is right-aligned (gap on the LEFT, not the middle).
- [ ] Resize down to ~100 cols (2 columns) and ~70 cols (1 column);
      transitions look reasonable, no orphan tile sitting alone
      below an empty column.

### C.8 Pi 4 detection (regression check, only if a Pi 4 is on hand)

- [ ] Bootstrap on a Pi 4 (or fake `/proc/cpuinfo` to look like Pi 4).
- [ ] Auto-detected platform = `x86` (intentional —
      Pi 4 is unsupported, falls through loudly).
- [ ] Install wizard refuses or fails clearly when applied to
      Pi 4 hardware (not silent disko-install onto incompatible
      arch).

## What to do if something fails

1. Capture `~/nixblitz.log` — line-buffered, every TUI action
   ends up there.
2. Note which step failed and the platform.
3. For Pi 5: also `journalctl -u electrs --no-pager -n 50` if
   the failure is service-side, or `dmesg | tail` for kernel /
   firmware hints.
4. For install failures: `journalctl -b 0 | grep -i error`
   inside the live image.

## Out of scope

- The Phase 1 contributor path (manual `nixos-rebuild switch
--flake .#nixblitz-pi5` on someone-else's aarch64 NixOS) is
  superseded by Phase 2 — don't bother retesting it.
- Plugin re-consent on signing-key change. We have unit tests
  for this; no good way to manually test without rotating an
  SSH key on the publishing repo.
- macOS dev — the FS watcher is Linux-only by design; nothing
  to validate there.
